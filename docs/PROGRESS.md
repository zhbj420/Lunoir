### ① 进度条缩略图

Yao 的需求：像 MPC 那样，悬停进度条看到那一帧，固定观感、不要花。拖动时不显示；IPTV / live / URL 不开。

**架构走了第二路。** 一开始按文档抄 MPC 的「第二个 mpv `--wid` 嵌进 Electron 小窗」，Chromium 合成器吃不下外部 D3D 帧——只能在窗口大事件瞬间亮一下，随即变黑。截图换 `<img>` 能出画，但跟手会跳。最终：第二个无声 mpv **自己开原生无边框窗**（`--focus-on=never`，Win32 `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`），DWM cloak 隐藏（`SW_HIDE` 会冻交换链）。主播放器完全不碰。

**画面：** 宽锁 320，高跟片源比例（2.35 变扁、4:3 变高、16:9 仍 180），底下一条灰底时间。悬浮贴 OSC 药丸上方 8px，停靠贴整条栏顶 12px，两套分开。点击与 hover 用同一套坐标，两边都 `absolute+exact`，点下去就是刚看到的那一帧。

**开关：** 设置 → Interface → Controls，「进度条缩略图」，默认开。关掉立刻收窗、停副 mpv。

**踩过的坑（别再走）：** `--wid` 进 Electron 窗；`screenshot-to-file` 换图；`SW_HIDE` 藏窗；DWM cloak 属性写成 17（那是 backdrop brush，正确是 13）；IPC 没连上就 `loadfile` 被丢掉→永远黑；OSD `--osd-shadow=0` 不是合法参数、副 mpv 直接退出还把主进程打崩。

## 当前状态（2026-09-04 · v0.9.3 发布 · URL 框原生编辑菜单 + Home 右键随处切换）

**阶段：URL 输入框右键终于能复制粘贴了（Electron 默认不画编辑菜单，可编辑字段右键本来什么都没有）；顺手把 Home 的右键入口从「按钮上那小块」放开到「任意空白」。加上社区 PR #2 的两处修复一起发布。i18n / subset-font / 构建全绿。**

### ① URL 输入框的原生右键编辑菜单

根子是 Electron 行为：不装 Menu 就没有 Chromium 的编辑菜单，input 右键什么都不弹，而 URL 框父级的右键逻辑只负责「关掉输入框」。修法两层：

- **主进程**给每个**可编辑字段**补原生 cut / copy / paste / selectAll，`params.isEditable` 守卫——非编辑区不碰，渲染层自有的右键（播放器菜单、片段 fps 菜单）原样拥有点击。
- **独立窗口必须各自注册**：侧面板（设置 / 播放列表）和收藏窗是独立 BrowserWindow、各有各的 webContents，主窗口的 handler 管不到它们。抽成 `attachNativeEditMenu()` 挂到主窗 / 面板 / 收藏三类窗口。
- 渲染端：URL 输入框与 UA 输入框 `stopPropagation`，右键只落到编辑菜单、不冒泡触发父级动作。

### ② Home 右键随处切换（打开文件 ⇄ URL 界面）

Yao 反馈：输入框右键改成编辑菜单后，「从 URL 界面右键回去」只剩播放按钮一个入口，藏太深。于是：

- 右键**任意空白处** = 两界面 toggle，入口从 open-btn / url-box 各自的局部 handler 收拢成空态层根上一个 handler。
- **输入框行为不动**：URL / UA 框右键仍是编辑菜单，stopPropagation 挡住 toggle。
- `.empty-state` 从 `pointer-events: none` 改 `auto`：无媒体时底下视频层只剩空操作（单击暂停 / 双击全屏），不亏；音量滚轮走 `.app` 根的 `onWheel`，冒泡不受影响；标题栏 z20 仍在最上。
- URL 界面加返回提示（`empty.urlBack`，九语言）：右键返回打开文件界面。Home 提示改为「双击打开文件夹 · **任意处右键输入 URL**」。

### ③ 顺手修了 i18n-check 的存量 bug

CRLF 行尾下 `extractValues` 的 `(.*)$` 把 `\r` 当行终止符 → **单行值 key 的占位符全读成空**，占位符检测形同虚设（只有多行值靠 trim 侥幸存活）。归一化行尾后检测真正生效，九语言占位符全对齐。这轮要不是新增 key 跑了一次检查，这个 bug 还会一直瞎下去。

- **fix: resume local and saved playlists**（max-wolf-cpp）——本地与已保存播放列表的续播恢复。

## 当前状态（2026-09-02 · v0.9.2 发布 · 放大查看 + 文件信息浮层 + 外挂音轨）

**阶段：两个用户痛点功能落地，加上社区 PR 合并。类型 / 构建 / i18n 全绿，Yao 实测通过。**

### ① Ctrl+滚轮放大查看（zoom/pan viewer）

Yao 的需求：「想放大画面观察画面细节」。

用 mpv 已有的 `video-zoom` / `video-pan-x` / `video-pan-y` 属性实现，零额外依赖。

| 手势 | 行为 |
| --- | --- |
| Ctrl+滚轮 | 缩放 25%–800%（log₂ 空间每格 ≈7%），右上角 OSD 显示百分比 |
| 左键拖拽（已放大时）| 平移画面；拖拽期间**暂停**以保证跟手，松手自动恢复播放 |
| Ctrl+双击 | 一键重置到 1×，pan 也归零 |
| 换文件 | 自动重置，下一个文件始终从 1× 开始 |

**普通滚轮继续调音量**，Ctrl 是分层的，和浏览器 / Photoshop 肌肉记忆一致。

**pan 的延迟问题经过两轮排查：**
1. 第一轮：rAF throttle（每帧最多一次 IPC），改善有限。
2. 第二轮：pointermove 的 `stopPropagation` 没加，事件冒泡到 `onMouseMove` 触发一堆 UI 可见性逻辑，和 IPC 同时竞争。加了 `stopPropagation` 后仍有卡顿。
3. 根本解法：**拖拽期间暂停**——mpv 渲染压力降下来，pan 立刻跟手。Yao 自己说「拖几下他暂停了就不卡了」，顺势变成设计。

暂停后 `onClick` 触发 `togglePause` 又把播放恢复翻转一次——用 `panJustEnded` 标志跳过那次 click 解决。

### ② 文件信息浮层（i 键）

Yao 的需求：「想有个界面可以显示文件的具体信息 如分辨率 编码 码率 颜色啥的」。

做成浮层（不混进右面板），按 `i` 键开关，点背景也能关。

**数据来源：** `runProbe()` 原本就跑 MediaInfo，`parseMediaInfo()` 扩展后额外采集：
- `General` track：容器格式、时长、**文件大小**、**整体码率**
- `Video` track：编码、分辨率、帧率、视频码率、色深、色彩空间、HDR 类型
- 所有 `Audio` track：商业名（TrueHD Atmos / DTS-HD MA…）、声道布局（5.1 / 7.1）、每轨码率

结果以 `video:info` 广播给 renderer，`VideoInfo` 接口加进 preload。

**磨砂问题：** CSS `backdrop-filter` 无法模糊 mpv 层（同标题栏 / URL 输入框的架构约束）。浮层背景用 `rgba(26, 26, 30, 0.92)` ——够厚能读，又不像 `0.97` 那么实，和整体风格统一。

**声道写法：** MediaInfo 给的是整数总数（6、8），`formatChannels()` 映射成环绕声标签（5.1、7.1）。

### ③ 外挂音轨加载（社区 PR #1，max-wolf-cpp）

合并自 [zhbj420/Lunoir#1](https://github.com/zhbj420/Lunoir/pull/1)。

- 右侧面板「音频」区新增「添加音轨…」按钮，支持 .flac / .dts / .truehd / .ac3 等格式。
- 所选音轨（内嵌或外挂）以 `ff-index` 为键存入 `audio-selections.json`，下次打开同文件自动还原，在 resume seek 之前生效。

### 发布说明

- 全部 9 个语言包补了 `info.*` 新 key（`info.overallBitRate`、`info.fileSize` 等）。
- fr.ts 历史遗留 bug：法语缩写的 U+2019 弯引号散布全文，esbuild 清缓存后全部暴露（和本次功能无关）。用 PowerShell 替换 UTF-8 字节 `E2 80 99` 为转义直引号修复，**此后 locale 文件里禁止用 Unicode 弯引号**。

## 当前状态（2026-08-13 · v0.9.1 发布 · 画面比例改成「裁进画框」）

**阶段：修掉右键菜单切比例会把画面拉变形的问题。类型 / 构建全绿,Yao 实测通过。**

### 画面比例:选 16:9 应该切掉上下,而不是把人拉胖

Yao 报的:「右键菜单切换比例会导致拉伸变形,而不是 fit」。

**病因是用错了属性。** 原来几项设的是 `video-aspect-override`,它的语义是「**这个文件标的 DAR 是错的,按 16:9 重新解释它**」—— 于是 4:3 的片子选 16:9,同样的像素被横向拉开填满,人就变胖了。它没坏,它本来就是干这个的:2000 年代修错标 DVD 转码的工具,不是构图控制。Yao 的原话:「现在一般没有什么比例不对的视频了 不是 20 年前」。

**改成 `video-crop` 居中裁切。** 源比例 srcAR、目标比例 dstAR:
- `dstAR > srcAR`(4:3 选 16:9)→ 裁高 → **上下丢掉**
- `dstAR < srcAR`(2.35 选 16:9)→ 裁宽 → **左右丢掉**

**逻辑从渲染层挪进主进程**,因为裁切矩形是**当前这个文件的像素**,换片必须重算(不然 16:9 的片子也会被砍掉 25%)。`video-params/aspect|w|h` 任一变化就跑一次 `applyAspect()`(幂等)。preset 跨文件保持,跟 MPC 一样。窗口模式下用**裁切后**的比例去 `fitWindowToVideo`,否则切完只是在另一个轴上把黑边买回来。「拉伸铺满」保留 —— 它是唯一诚实地承认自己在变形的那项。

**动手前拿 mpv 的 IPC 实测过四条**(都不是从文档推的,推错了就是白干一轮):

| 验的东西 | 结果 |
| --- | --- |
| 运行时设 `video-crop` 后 `video-params/aspect\|w\|h` 会不会变 | **不变**(始终 1.333 / 640×480)→ 每次重算都基于原始尺寸,**不会「裁了再裁」滚雪球**;裁切后的比例在 `video-out-params/aspect` |
| 不给偏移量是不是居中裁 | **是**。`320x480` 与手算居中的 `320x480+160+0` 渲出的帧 md5 完全一致,和左对齐的 `+0+0` 不同 |
| 百分比形式能不能用小数 | **不能**。`100%x75.0000%` 直接解析失败退出(`Valid format: W[%][xH[%]][+x+y]`,整数)→ 所以最终走**像素**而不是百分比,精度才够 |
| preset 跨文件保持时,大片子的裁切矩形撞上更小的新片子 | **mpv 静默忽略、退回整帧**,不报错不黑屏;随后我们的重算把它修正 |

九国语言一个 key 没动,`subset-font` 也不用跑。

## 历史状态（2026-08-10 · v0.9.0 发布 · 底部停靠 OSC 第一刀 + 最近记录清空）

**阶段：动工做规划已久的「底部停靠 OSC」,第一刀(机制)完成并由 Yao 实测通过;顺手补了收藏「最近」的清空入口。类型 / 构建 / i18n 全绿。**

### ① 底部停靠 OSC —— 设置可切换的第二种控制栏
`oscStyle: 'floating' | 'docked'`,默认 floating(不动老用户现状)。停靠时贴底通栏、直角、侧面板开着就缩短。

**让位方式是 Yao 拍的板:窗口长高 `DOCK_H`,画面尺寸不变**(而不是画面缩小)。退化路径写全了 —— 顶到工作区底边 / 最大化 / 全屏时窗口长不动,那时改由视频让出这条 strip(`video-margin-ratio-bottom`,和标题栏 `-top` 同一套机制)。

**常驻**:`dockPinned()`(停靠 + 窗口模式)时,自动隐藏计时到点只收其余 UI,栏不动 —— 因为那条 strip 视频已经让出来了,藏了只会露一条纯黑。

**收敛出一个 `hideUi()`**:原本「弹出层出现就藏 OSC」散在四处(计时器 / 右键菜单 / 收藏面板 / 小窗),停靠时每次右键都会闪一条黑洞。统一成一个函数,pinned 时只藏别的、留下栏;**真正该藏的两条路径**(回主页、进小窗)仍直接调 `broadcast + animateOsc`,不走这个豁免。

`fitWindowToVideo()` 把这条栏计进了 `chrome`(= 标题栏 + `dockReserve()`)—— 记忆里点名的坑,不扣就把「适应视频比例」算歪一个栏高。

### ② 单排布局 —— 停靠的意义是省高度
Yao 的诉求:既然在下面,就不该占地方。于是折成一排:

```
⏪ ▶ ⏩ │ 时间 ━━━●━━━ 时间 │ 音量 │ 格式标 │ ⭐ ⚙ ☰
```

`DOCK_H = 56`(悬浮是 92)。**播放控件保持原尺寸**(44px 播放键 / 36px 前后退)—— 那是真正要点的东西,让栏高去适应它,而不是压小它凑高度;其余(音量、格式标、右侧三个)走小尺寸。格式标从竖排堆叠改横排。

**悬浮样式一个字节没动** —— 那套 IINA 比例是锁的(见 CLAUDE.md 的排版铁律)。实现上把元素抽成共享块(`transportGrp` / `seekBody` / `fmtBadges` …),进度条那堆东西(A-B 标记 / 片段分界 / trim 手柄 / LIVE 变体)只有一份。

**踩到的两个 CSS 坑(都是「悬浮的规则跟着搬过来」)**:
- 容器只写了 `osc-seek`,可 flex 是 `osc-row` 给的 → 那一段退化成块级,时间和进度条**竖着叠三行**,高度撑爆被窗口切掉。
- `.grp.right { flex: 1 }` 是给悬浮写的(右侧组独占一行,靠拉伸把按钮顶到最右)。单排里它跟进度条**两个 `flex: 1` 平分剩余空间** → 格式标后面空一大块。改成 `flex: none`,**整排只有进度条会变长短**。

### ③ 底边拖不动 —— 旧账新用
无边框窗口的缩放热区就是它最外圈像素,而停靠栏是**独立子窗口**正好压在上面 → 底边和左右下角全拖不动。**这病侧面板得过,`ResizeGrips` 就是当年的解药**(贴透明条 → IPC 改主窗口 bounds),原封不动复用,只给类型加了 `export`。

**跟面板那次的差别**:面板认领的边是固定的,停靠栏不是 —— 面板开着时栏被缩短,那侧变成窗口内部,给 resize 光标就是骗人。所以边集合由主进程算、推给 OSC:

| 状态 | 认领的边 |
| --- | --- |
| 停靠 + 窗口 + 无面板 | `s` `w` `sw` `e` `se` |
| 停靠 + 播放列表开着 | `s` `w` `sw`(右下角归面板) |
| 停靠 + 设置开着 | `s` `e` `se`(左下角归面板) |
| 全屏 / 最大化 | 无 —— 本来就不能缩放,给个没用的光标更糟 |
| 悬浮 | 无 —— 药丸离边框很远 |

### ④ 收藏「最近」的清空入口
后端早就齐了(`clearRecents()` + `library:recents-clear` + `recents:changed`),缺的只是界面。放在**标签行右侧、关闭按钮左边**:作用于整个列表,跟每行的单条删除天然分层;只在「最近」且非空时出现。

**两段式确认**:第一下变红字「确认清空？」,再点才真清,3 秒无操作 / 切标签 / 失焦都退回。**项目里没有任何 modal**,不为一个按钮引一个。

### ⑤ 首次启动窗口空白 —— 「加载成功」不等于「界面起来了」
现象:冷启 `npm run dev`,OSC 只有一片灰亚克力、控件全无,第二次就正常。**停靠模式下这个 bug 格外显眼** —— 底部那条 strip 是留出来的(视频真的让位了),里面却空空如也。

**我第一版判断只对了一半。** 起初以为是「文档加载失败 → `did-finish-load` 永不触发」,加了 `did-fail-load` 重试 —— 结果没救到复现的那次。真相是**另一条路**:

> `index.html` **加载成功了**,但它的**模块脚本没成功**。`createWindows()` 连着加载五扇窗,第一次请求会让 Vite 去做依赖预打包(re-optimise),**这期间到达的模块请求被 504 打回**。于是文档 OK → `did-finish-load` 照常触发、`did-fail-load` 永远不来 → 主进程以为这扇窗好了,而 React 根本没挂载。同时 reveal 那条路照样 `showInactive()`,于是一扇空的磨砂窗被显示出来。

Yao 那张截图正是铁证:**strip 留对了说明主进程这半边全跑通了,空的是渲染器。**

**修法 = 握手**。光看加载事件永远分不清这两种失败,所以让渲染器自己报到:`main.tsx` 在 `ReactDOM.render` 之后发 `ui:renderer-ready`(能走到那一行 = 整条 import 链执行完了)。主进程收 ping,**4 秒等不到就重载那扇窗**。

收敛成一个 `loadRendererWithSetup(win, query, setup)`,**五扇窗全用它**(原先四扇子窗各写一遍 `once('did-finish-load')`,主窗**一层保护都没有** —— 而主窗恰恰是**第一个加载、也就是触发预打包的那个**,它的脚本要是输了这场比赛,整个 app 就是个空磨砂矩形)。三个细节:
- **`on` 而不是 `once`**:setup 幂等,这样 HMR 重载 / 渲染器崩溃后也会重跑 —— 以前这两种情况同样留下半死窗口。
- **`did-start-loading` 时清掉 ping 旗标**:否则「挂载过一次、然后重载进坏模块」的窗口会揣着旧旗标,永远不再重试。
- **`startMpv()` 留在 `ready-to-show`**,不能进 setup —— 那玩意儿不该跟着重载再跑一遍。

生产走 `file://`,基本碰不到第二种失败,但这层兜底很便宜。**类型 / 构建绿,运行时待 Yao 冷启几次验。**

### ① 关闭弹出层的那次点击,必须被消耗掉
现象:右键菜单开着时左键点画面,菜单关了,**视频也暂停了**。

根因是"两件事同时发生":菜单是**独立窗口**,靠 `mw.on('blur', () => hideMenu())` 关闭;而视频层挂着 `onClick={p.togglePause}`。那一次左键既让菜单窗口失焦(关菜单)、又落到了下面的视频上(暂停)。**Windows 上所有弹出菜单的规矩都是:让菜单消失的那一下,只做消失这件事。**

收敛成一条规则,并且顺势覆盖了 Yao 提的第二个诉求:

> **右键永远先"关掉当前开着的东西";没东西可关时,才弹菜单。**

于是:
- 左键关菜单 → **不暂停**
- 右键在别处 → **只关菜单**,不在新位置重开一个
- **侧面板开着时右键 = 关面板**(菜单变成再右键一下)—— 代价是面板开着时用菜单要两下,但规则可预期,而且和上面同源

**踩到的坑:这里有竞态,不能只判 `menuOpen`。** 关闭是**主进程**(菜单窗口 blur)决定后广播过来的,点击却是**渲染器**自己派发的,**两者到达顺序不保证** —— 点击跑到广播前面时 `menuOpen` 还是 true,跑到后面就已经是 false 了。所以判据做成"**还开着 或 刚关掉不到 250ms**",两种顺序都兜住。双击(全屏)也上了同样的保护,免得"关菜单那下 + 紧接一下"变成全屏。

之前 **Esc 全局没绑任何东西**(只有右键菜单和网址输入框各自接了)。补上,并且只做"退出",绝不用来**进入**全屏。

## 历史状态（2026-07-27 · v0.8.2 发布 · Emby 外挂字幕 + 轨道语言名 + 分辨率标修正）

**阶段：接着 v0.8.1 往下补 Emby 这条链 —— 把服务器索引过的外挂字幕也取过来;顺带把「轨道语言怎么显示」和「分辨率标」两处积年的糙活做干净。类型 / 构建全绿(本轮无 i18n 改动 —— 见下,语言名是 ICU 出的)。**

### ① 外挂字幕:HTTP 播放时它们是隐形的
现象:`Y:\Movies4K\Supergirl.(2026)` 里躺着 4 个 `.ass/.srt`,从 Emby 播**一个都没挂上**。

原因是结构性的:mpv 的 `sub-auto=fuzzy` 靠**扫描媒体所在目录**找同名字幕,而播的是 `http://…/original.mp4?…`,**URL 没有"所在目录"**,自然扫不到。

但服务器**早就索引过它们**。`Fields=MediaSources` 挂在标题那次请求上(**不多发一次**),挑出 `IsExternal && IsTextSubtitleStream`,拼出:

```
{base}/Videos/{itemId}/{mediaSourceId}/Subtitles/{index}/Stream.{ext}?api_key=…
```

`ext` 按 Codec 取原生格式(ass→ass),实测 **ASS 拉下来仍是 `[Script Info]` 原生样式,没被服务器转成 SRT**。

**两个坑**:
- **轨道名靠 `Title` 才能区分** —— 那 4 条的 `DisplayTitle` 全叫 `Chinese Simplified (ASS/SRT)`,只有 `Title` 字段写着 `简英`,不然双语和普通版在面板里一模一样。
- **`auto` 标志会让字幕语言设置落空** —— mpv 在**开片时**就选好了轨道,我们的字幕是之后才到的,用 `auto`(加了不选)等于永远不选。改成自己挑:第一条匹配「字幕语言」设置的用 `select`,没设偏好就一条都不强选(**和本地文件同一个规矩**,是 Yao 选的方案 A)。
- **时序两头兜**:反查和开片在赛跑,谁后到谁负责挂;中途切片子会作废上一次的结果。

### ② 轨道语言名:一张写死的英文表
`LANG_NAME` 只认三字母码、只出英文、简繁不分 —— `zh-CN` 查不到就原样喊回来 **`ZH-CN`**,`chi` 一律 "Chinese",界面切成中文轨道名还是英文。

**关键发现:Chromium 自带完整 ICU,`Intl.DisplayNames` 能按当前界面语言给出语言名** —— 所以**九种界面语言全免费,一个 i18n key 都不用加**:

| UI | zh-Hans | en | ja |
| --- | --- | --- | --- |
| 中文 | 简体中文 | 英语 | 日语 |
| English | Simplified Chinese | English | Japanese |
| 日本語 | 簡体中国語 | 英語 | 日本語 |

于是做法变成:**把五花八门的写法归一到 BCP-47 标签,再交给 ICU 命名**(`src/renderer/src/langLabel.ts`)。调研到的写法:

| 归一到 | 写法 |
| --- | --- |
| `zh-Hans` | chs、sc、gb、gbk、cn、zhs、zh-CN / zh_CN、zh-Hans、简、简体、简中 |
| `zh-Hant` | cht、tc、big5、tw、hk、zht、zh-TW / zh-HK、zh-Hant、繁、繁體、正體 |
| `zh` | chi、zho、zh、中文、中 |
| 双语 | chs&eng、**ChsEng**(驼峰)、chs_eng、sc&en、zh-en、**简英**(中文连写)、中英、繁英、双语 |

双语有**三种粘法**要分别处理:分隔符 / 驼峰 / 中文单字连写。`SDH`、`Forced`、`特效` 这类描述词保留,不当语言。

**优先级:标题里认出语言 > 轨道的 lang 标签。** 这条正好吃国内片源最常见的做法——语言一律标 `chi`,靠标题写 简体/繁體 区分;`chi` 单独出现时诚实显示"中文",**不猜简繁**(它本来就不带字形信息)。音频轨也换用同一套。

### ③ 分辨率标把宽银幕电影读小了
OSC 上的角标印的是**解码高度**,而 2.40:1 的电影**不存黑边**(截图里那两条是显示器补的),于是:

| 片子 | 编码 | 旧显示 | 应为 |
| --- | --- | --- | --- |
| Dragon Tattoo | 1920×800 | ~~800p~~ | 1080p |
| Honor Among Thieves | 3840×1608 | ~~1608p~~ | 2160p |

改成 `档次 = max(高, 宽×9÷16)` —— 宽银幕走宽度,4:3 老片(1440×1080)走高度,**两边都不能只看一个**。再吸附到标准档,免得裁过的片出 `1076p`。**吸附要取"最接近"而不是"第一个落在容差内"**:544 落在 576 的 6% 容差里,但它明明是 540p(这条是自测时逮到的,数组顺序会坑人)。

(本地播放**不显示**这个标 —— 一直是这个设计,"本地你自己知道画质"。)

沿用 v0.8.1 那套"先量后改",而且这次是**在发包之前**跑的:
- **字幕**:拿真实条目跑一遍构造逻辑,再真去拉那 4 条 —— 全部 HTTP 200、拿到内容。

## 历史状态（2026-07-26 · v0.8.1 发布 · 接进 Emby:能播 + 认得出片名 + 续播真的续得上）

**阶段：把 Lunoir 接进已有的媒体库工作流 —— Emby 网页点播放直接在 Lunoir 里开。一个功能带两个坑,三件事都是「先量后改」量出来的。类型 / 构建全绿(本轮无 i18n 改动)。**

桥接工具 [embyToLocalPlayer](https://github.com/kjtsune/embyToLocalPlayer) 负责把 Emby 的播放动作转给本地播放器。它在 `embyToLocalPlayer_config.ini` 里指到 Lunoir 后:**窗口能弹出来,但不起播。**

### ① 命令行不认 URL（这才是不起播的原因）
从进程表里把真实命令行读出来 —— `Get-CimInstance Win32_Process`,一眼看到:

```
Lunoir.exe http://192.168.50.91:8088/emby/videos/256818/original.mkv?…&api_key=…&Static=true
```

**一个裸的 http 地址,没有任何其它参数。** 而 `fileFromArgv()` 最后一关是 `existsSync(p)` —— URL `resolve()` 之后成了 `D:\…\http:\…`,自然不存在 → 返回 null → 窗口开了、片子没进来。放行 URL 即可(`isUrl(raw)` 提到 `existsSync` 前面),顺手更名 `targetFromArgv`(返回的已不只是"文件")。**两个入口都要改**:启动 argv,以及单实例的 `second-instance`(Lunoir 已经开着时再点播放走的是后者)。

讽刺的是 URL 播放**本来就支持**(拖网址进来就能放,同一个 `openMedia()`),只是命令行这条路没放行。

### ② 标题是一长串 query string —— 那就自己去问
`--force-media-title` 是 embyToLocalPlayer 喂给**适配过的**六个播放器(mpv / PotPlayer / MPC / VLC / IINA / 弹弹play)的,Lunoir 不在名单里,一个参数都拿不到 —— 所以 MPC 那边同样没标题。

但**URL 自己带着答案**:`…/videos/**256818**/…?…&**api_key=…**`,条目 ID 和钥匙都在。一个 GET:

```
{server}/emby/Items?Ids={id}&api_key={key}
→ SeriesName / ParentIndexNumber / IndexNumber / Name / ProductionYear
```

拼成 `剧名 · S01E01 · 集名`(剧集)或 `片名 (年份)`(其它),铺到标题栏 / OSC / 播放列表 /「最近」(`updateRecentName()` 本来就是给"URL 拿到真名后再修正"用的)。**不引入新依赖**(全局 `fetch`,和检查更新同一套)。Jellyfin 路径形状一样(`/Videos/<id>/`),顺带支持。

**全程 best-effort**:服务器不通 / key 失效 / 认不出的返回 → 6 秒超时后**静默保持原状**,绝不弹错误。发包前用真实 URL 离线验过三条用例:真地址出真名、YouTube 不误伤、缺 api_key 不动作。

**沿用旧坑的教训**:`force-media-title` 必须在 `loadFile` **之后**设(IPTV 那轮踩过),而且反查是异步的 —— 落地时要先确认 `playlist[plIndex]` 还是当初那个目标,否则会把标题盖到用户已经切走的片子上。

### ③ 续播"记了等于没记"
`positions.json` 里翻出实据:那一集**只有一条**记录,键是整条 URL、里面嵌着 `PlaySessionId=e4ce6e8a…`。而 **Emby 每次播放都新发一个 PlaySessionId** —— 键次次不同 → 上次存的永远找不回来,而且每播一次多攒一条孤儿记录。

改成用**条目 ID** 当键(`emby:host/256818`)。落点只有一处:`resumePath = positionKey(data)`,存/读/清三处自动跟着走。

### 下一轮：Emby 双向进度同步（有意留到单独一轮）
真正的正解是**回传进度** —— Emby 成为唯一事实来源:手机看到 20 分钟换电脑接着看、看完自动标已观看。料都在手上了(api_key / item id / PlaySessionId,后者正是回传接口要用的)。接口是 `/Sessions/Playing` → `/Playing/Progress` → `/Playing/Stopped`,续播点读 `UserData.PlaybackPositionTicks`。

**为什么不塞进这一版**:读和写必须一起上。只读不回传的话,Emby 那边的进度永远不动 → **每次都从同一个陈旧的点开始**,比现在更让人困惑。③ 那个本地键将来也留着 —— 断网或回传失败时的兜底。

### 画质增强（设置 › 视频 › ENHANCEMENT,总开关默认关）
五件套,各自独立,总开关一关整块不生效(干净片源绝不碰):

| 控件 | 后端 | 侧 | 默认 |
| --- | --- | --- | --- |
| 去块 | `uspp=quality=2/3/4` | 解码侧 vf | 中(3) |
| 降噪 | `hqdn3d=…:0:0` 低/高 | 解码侧 vf | 关 |
| 锐化 | `unsharp` 0–2 | 解码侧 vf | 0.2 |
| 细节超分 | ArtCNN_C4F16(LUMA 2×) | 渲染侧 shader | 关 |
| 色度重建 | CfL_Prediction(CHROMA) | 渲染侧 shader | 关 |

- **三个 vf 共用一条 lavfi 链,任一开启就借 `hwdec=auto-copy`**,全关时把 hwdec 还给用户设置。CPU 滤镜读不了 d3d11 的显存帧,不切 auto-copy 的话 mpv 会**静默禁掉整条 vf 链**。uspp 没有 GPU 版替代品,这个 copy 是它绕不开的入场券。
- **ArtCNN 开启时 `scale` 从 `ewa_lanczossharp` 降为中性 `lanczos`** —— 它自己就是亮度放大器,再叠 ewa 的锐化会过冲。CfL 只管色度,不动 `scale`(规则 B)。ArtCNN 自带 `WHEN OUTPUT/LUMA > 1.3` 守卫,原生分辨率下自动罢工。
- shader 打进 `resources/shaders/`(**不运行时下载**,上游 URL 会烂),并用打包的 mpv 离线冒烟验证过:20 次 `shaderc compile status success`、0 错误。
- 参照 `classicjazz/mpv-config`(专业配置)的 ArtCNN+CfL 搭配。**但他们整条链没有去块** —— 他们的片源是干净的;去块是 Lunoir 针对脏 IPTV 自己的那块。
- 真机结论(脏直播源上排序):**锐化 ≫ 去块 > ArtCNN / CfL(微弱)**。重建是给"干净但低分"的素材用的,压缩烂源上它没有干净底子可推理。整体"不如 madVR 但可用" —— 我们是轻量无副作用这一档。

### 修复：音量到不了自己的上限

### 硬碰硬的一条：Chromium 不会主动重新应用 `cursor`
全屏下光标有时不肯自动隐藏。**状态全是对的** —— 后台诊断打出 `UNDER=DIV.video-surface COMPUTED-CURSOR=none`,样式算出来就是 `none`,箭头却还在屏幕上。

**根因:Chromium 只在处理鼠标事件时才把 `cursor` 应用到 OS。** 而开启 `cursor:none` 靠的是 class 变化,那一刻指针**静止不动**,没有任何事件 → 它算完了却送不出去。用户点一下、或退出再进全屏(resize),都是在人工制造那个事件 —— 所以看着像"手动就能修好"。

修法:在启用 `cursor:none` 的时刻(UI 隐藏 / `.cursor-active` 到期)由主进程合成一次 `mouseMove`。**必须偏移 1px** —— 落在同一点的 mousemove 会被 Chromium 丢弃。渲染端相应把 `≤1px` 视为"没动",这一下就不会把刚收起的 UI 又叫醒。

顺带逮到两个能单独把它卡死的隐患:
- **"没移动的 mousemove"**。光标下方窗口出现/消失/移动时 Windows 会在**同一点**补发一个 —— OSC 正是这种窗口。指针停在底部那条带里会自锁:OSC 隐藏 → 合成移动 → 又被唤醒 → 循环。规则:**坐标没变就不算移动**。
- **opacity 0 但仍 shown 的窗口,照样占着它矩形内的光标**。`setIgnoreMouseEvents(true)` 只放行**点击**,不放行光标。收藏和右键菜单窗口为了首开不播放 Windows 缩放动画被故意留成 shown+透明,而它俩几乎铺满屏幕。改成空闲时**停泊到 1×1**(预热保留、不再占屏)。注意别用 `isVisible()` 判断要不要重新布局 —— 停泊中的窗口也是 visible,会被叫醒。

排查路径值得复用:**从主进程定时问渲染器"光标底下是哪个元素、它算出来的 cursor 是什么"**(`elementFromPoint` + `getComputedStyle`)。一行日志就砍掉了全部"某个状态卡住了"的假设。细节见记忆 `electron-cursor-not-reapplied`。

### 试过又撤掉的
- **adaptive-sharpen** —— 边缘自适应、带过冲钳制、渲染侧(不用 auto-copy),观感也好,但**强度旋钮不可用**:低于某个阈值完全看不见,过了就一档到顶,中间没层次。(另:它真正的强度参数是 `#define curve_height`,不是 `curveslope`;我先接错了,接对之后依旧是二元的。)最终换回**普通 unsharp** —— `luma_amount` 线性,滑块才像滑块。
- **SSimSuperRes** —— 被 ArtCNN 取代。它本质是"消除内置缩放器振铃"的修正 pass,不是重建器。
- **时域降噪**(hqdn3d 带时域项)—— 确实更干净,但**任何镜头运动都会拖影**(ffmpeg 的 hqdn3d 不做运动补偿),航拍平移一眼就看出来。索尼电视那种"又猛又干净"靠的是运动补偿专用硅片,轻量滤镜复刻不出。**天花板认了**:只能选"保守无 artifact",时域项永久钉死 `:0:0`。
- **ravu-zoom**(任意倍数上采样,专业配置用来补 ArtCNN 只会整 2× 的短板)—— 需要多打一个 shader + 运行时判分辨率切换,收益只在 720p→1080p 这类怪比例上,不值。
- **mpv 只在 `glsl-shaders` 的值变化时重载** —— 固定文件名改内容**不会重载**,滑块看着完全失灵。参数化 shader 必须**把参数写进文件名**。(静态开关的 shader 没这问题:增删路径本身就是值变化。)

### 小窗模式（PiP）
- **同一个窗口**缩到角落 + 置顶 + 收起标题栏,**不做重新挂载** —— mpv 本来就渲染在这个窗口里,所以整个模式 = bounds + alwaysOnTop + `setAspectRatio`,复用全屏那套 `preFsBounds` 存/还原的写法。默认 480px 宽,按视频宽高比算高。
- **控件画在主窗口 DOM 里**,不再开第四个亚克力子窗口:CSS 本来就磨砂不到 mpv 画面,而 ~480px 上一层普通 scrim 才是对的。**正中一个大播放键 + 右上角退出 + 底部只读发丝进度**;OSC 那排图标在这个尺寸下每个只有几像素。
- **缩放自由但锁比例**,两端都有界:低于 ~240px 什么都看不清;放得过大则是"标题栏、OSC、面板、播放列表全交出去了却一样没换回来",普通窗口在每一项上都更强 —— 所以封顶 55% 工作区、不超过 1100px。系统级 PiP 一律有上限,同一个道理。
- 与全屏**互斥**;进入时关掉侧边栏/收藏、OSC 整个隐藏、`revealUi()` 直接 return;「返回主页」时若在小窗会先退出。
- **悬停判定放在主进程**(轮询光标 vs 窗口矩形,150ms,仅小窗期间)。渲染端的 `:hover` 在这儿是假的 —— 见下。

### 隐藏标题栏（窗口模式）
- 右键菜单开关,存设置。画面通到顶边,**光标靠近上方时标题栏滑回**(它握着拖动区和三个窗口按钮,必须能回来)。触发带**故意做宽**:第一版用顶部几像素,几乎点不中 —— 无边框窗口最外圈是**系统缩放热区**,DOM 根本看不到那么靠上的光标。
- 标题栏是**盖在画面上**而非重新占位(主进程两种情况都把视频上边距置 0),所以浮现时画面**不会跳**。
- "标题栏在不在"收敛成单一判据 **`noTitleStrip()`**,视频边距 / 侧边栏 / 收藏面板三处共用。以前各写各的 `preFsBounds ? 0 : TITLEBAR_H`,每加一种模式就要改三处、漏一处就错位。

### 其它
- **从浏览器地址栏(或网页链接)拖网址进来直接播**。拖网址没有 `dataTransfer.files`,只有文本,所以原来的 drop 处理器什么都不做。改成回落到 `text/uri-list` → `text/plain`,取第一条 http(s);拖普通文字**不会**误触发,拖 `.m3u` 订阅地址照样走频道单那条路。
- **退出时保存的是"要还原到的矩形",不是当前的**。从小窗按任务栏关闭,原来会把角落那个小矩形存下来、下次开出个小窗口。最大化那条早就这么处理了,小窗是后加的漏了。

### 硬碰硬的一条：不要用 `-webkit-app-region` 做小窗拖动
Windows 把拖动区当**标题栏**看:右键弹**系统窗口菜单**,而且该区域的鼠标事件在到达 DOM 之前就被系统拿走 —— 悬停收不到、`preventDefault` 拦不住、双击归系统(当初"双击退出会弹回"就是它和系统的最大化/还原打架)。所以改成**手动拖窗**,鼠标事件全部回到自己手里,顺带才有了小窗**自己的短菜单**(上/下一个 · 上/下一章 · 全屏 · 退出)。

**手动拖窗改了三版,三次栽在同一个坑:把窗口自身状态读回来当作下一次调用的输入。**

| 版本 | 反馈路径 | 症状 |
| --- | --- | --- |
| 一 | 读 bounds 加偏移写回;宽高比锁着 → 每次都重新贴合 + 取整 | 越拖窗口**越大** |
| 二 | 尺寸钉死了,但**位置**仍走 `getBounds()`;IPC 异步,上一步没落地就被当起点 | 越拖**越落后于光标** |
| 三 | 按下时锚定窗口矩形 + 光标位置,之后全部 `锚点 + 光标总位移`,**零读回** | 干净 |

结论写进注释了:**有"读回来→改一点→写回去"的回路就会漂,换哪个 API 都没用**(`setPosition` 也不行,Electron 内部照样走 `SetBounds`)。丢事件也无所谓 —— 下一个事件算出的仍是正确的绝对位置。

## 历史状态（2026-07-23 · v0.7.1 发布 · 直播实战修复 + 界面打磨）

**阶段：拿一个真实的 IPTV 订阅源实测,挖出三个普通用户必踩的 bug,顺带补了两处一直没做对的体验。类型 / i18n(9 语言 243) / 构建全绿。**

### 修复（都是真机撞出来的）
- **带查询参数的 m3u 订阅地址被当成单个视频打开**。频道单识别写的是 `/\.(m3u|txt)$/` —— 结尾锚点。而订阅地址普遍长这样:`https://host/iptv.m3u?userid=…&auth_token=…`,结尾是 token 不是 `.m3u`,于是**漏判**,mpv 顺着 m3u 自己播了第一条,221 个频道的列表看上去像一个视频。改成 `CHANNEL_LIST_EXT = /\.(m3u|txt)(\?|#|$)/i`(同文件里 `MEDIA_URL_EXT` 早就是这么写的);`.m3u8` 靠结尾那个 8 照样被排除。
- **切台会弹「Resumed from …」**。直播的 `time-pos` 只是"你看了多久",却被当成播放进度存进 `positions.json`,切回该台就 seek 进直播边缘 + 弹提示。`canResume()` 在**存和取**两头把闸:`sourceType !== 'iptv'`(确定性,不依赖 `seekable` 何时到达)且 `lastSeekable !== false`(兜住单独打开的直播 URL);默认放行,本地文件/VOD 续播不受影响,并会**顺手清掉**此前误写的频道记录。
- **滑动窗口 HLS 的台不显示 LIVE**。这类流 `seekable` 报 **true**(mpv 能在播放列表里现存的分片间跳),`duration` 等于那个窗口(几十秒),于是画出一条随窗口滑动不断重新定基的进度条。频道按定义就是直播,`isLive` 改为 OR 上"正在播频道列表",不再听流自己怎么说。

### 新增
- **逐源 User-Agent**(打开 URL 框下方折叠的 Advanced,右键入口和 Home 入口共用)。有些源只把真实流给自家 App 的 UA,其余一律 302 到占位片 —— 实测同一条频道 URL:不带 UA 跳 `testvideo` CDN,带 UA 跳广播方 CDN,这就是"221 个台全在放同一个测试片"的原因。**它是源的属性不是播放器的属性**:作用于该源的列表抓取 + 频道播放,存进收藏项(`FavEntry.userAgent`)以便重开时不用重填,每次打开都被覆盖 —— 别的源/文件/在线视频绝不会带着别人的 UA。(先做过一版全局设置,因为"两个源需要不同的值"而推翻。)
- **音轨解不出来时说清楚**。信号是实测的:音轨已选中(mpv 报了 codec)但**始终拿不到声道布局**。AV3A(菁彩声)就是这样 —— demuxer 探测失败(`probed stream 1 failed`),退回按 TS stream_type 猜一个 codec,实际一个采样都不解。延迟 5 秒判定(声道信息本来就比 codec 名晚到),真声道一到立刻撤销。两层呈现:**徽标常驻 `Unknown`**(demuxer 连识别都失败,这比"不支持"更准),**toast 一次性**说明只有画面。
- **右键菜单「返回主页」**。停播 + 清空队列/当前项/频道快照/时间线合并·裁剪·逐片段帧率/源 UA/续播跟踪,速率归 1(时间线片段可能占着它);渲染端复位媒体状态但**保留音量与静音**(那是用户的,不是文件的)。

## 历史状态（2026-07-23 · v0.7.0 发布 · 逐片段播放帧率 + 时间线片段追踪修复）

**阶段：给实验性时间线补上「高帧率素材变真慢动作」——但做成了 *逐片段* 而非全局;顺带修掉两个只有真机才看得见的问题。类型 / i18n(9 语言 233) / 构建全绿。**

### 逐片段播放帧率（实验性时间线内）
- **CLIPS 面板右键任意片段** → `原始帧率 / 24 / 30 / 60`。低于该片拍摄帧率即**真慢动作**(120fps 片子按 30 播 = 4 倍慢)。按**路径**存(仅本会话,随重排走,与 `trims` 同模型)。
- **实现**:mpv 的 **`speed` = 目标 ÷ 该片真实帧率**;真实帧率用自带 MediaInfo(`--Inform=Video;%FrameRate%`)按路径探一次并缓存,过片段分界时重设(`applyClipSpeed()`,挂在 `chapter` 处理里)。**时间线与 trim 都生效**(trim 即所见即所得),所以速率**只有右键这一个入口** —— 时间线内(含 trim)**隐藏右键倍速项**,不给第二种改速率的方式。
- **对外只讲「帧率」**:README / release notes 描述的是"给片段设播放帧率",底下用 speed 换算属实现细节,只写在代码注释里。
- OSC 不再显示倍数而是**帧率**:有覆盖显示覆盖值(**蓝色**,呼应面板里的 `.pl-fps` 蓝标),否则显示该片**原生**帧率;混帧率队列跨分界会自动换成下一段真实值。
- **实测不变量**:`speed` 不碰时间戳 → `duration`、片段分界、**trim 范围**全都不随帧率设置漂移(带/不带覆盖测得完全一致)。

### 更正 v0.6.0 那条搁置结论（上一条目 line「搁置」）
- 当时记的"`--container-fps-override` **不穿透 EDL**"**是错的** —— 漏了 `--correct-pts=no`。补上后它**确实穿透**、也确实产生慢放(实测 59.94fps 片子钉到 30,`container-fps=30`、0 丢帧、`time-pos`/`duration` 仍走原生时钟所以进度条不溢出)。
- 但这条路**另有硬伤**才被放弃:**音频不跟着慢** → 在拼接流里越播越偏,混了慢放片段就得整条静音;且它覆盖 `container-fps`,使**帧号退化**(每原生秒出 59.94 张画面而计数只走 30 → 两张不同画面共用一个帧号)。`speed` 三样毛病都没有(声画同步、变调已校正、不碰 container-fps)。
- **为何逐片段只能靠 `speed`**:查过官方 EDL 规范,每段可带的参数只有 `file / start / length / title / layout / timestamps`,**没有任何 per-segment 的帧率/速度/解复用选项**。`speed` 可行纯粹因为它是**运行时属性**。

### 修复
- **时间线片段追踪原来是坏的**:拼接后的 `chapter-list` 会把**源文件自带的章节**混进来(蓝光 rip 动辄十几个),而代码把 chapter 索引当片段索引 → 播过第一片后 ▶ 高亮丢失、点片段/上下一个跳错。现按 **mpv 给分界章节的 `title` 恰是我们写进 EDL 的那条路径**筛出真正的分界(`clipStarts`,plain 与 trim 过的 `path,in,len` 都实测成立),进度条刻度/当前片段/片段跳转全走它;跳转改 `seek <分界> absolute exact`(关键帧 seek 会落到分界前一帧、掉回上一段)。`!no_chapters` 不能用 —— 规范说它连"从源区间复制"一起停,实测分界也没了(count=0)。
- **右键菜单开在面板背后**:菜单窗口与面板是同级子窗口,`focus()` 不保证重排 z 序,从面板右键时菜单被压在面板下、透过亚克力成一团糊影,要按第二次才上来。修法:reveal 时先 `menuWin.moveTop()` 再 `focus()`。

### 面板
- 时间线开启时:播放列表标签改称 **CLIPS / 片段**,**CHAPTERS 标签隐藏**(源章节在这里没有意义)。两者都是**派生**的,关掉时间线自动还原,不吃用户的标签选择。

## 历史状态（2026-07-22 · 修复 mpv stdout 管道憋死播放器 · v0.5.1）

**阶段：修一个 v0.5.0 就带着的潜在死锁 —— 看直播切几次台后整个播放器卡死在 `Loading…`,连之前能看的台也 load 不了,必须重启 Lunoir。根因不在直播逻辑,在子进程管道。**

- **根因**:`MpvController`([mpv.ts](../src/main/mpv.ts))spawn mpv 用 `stdio:['ignore','pipe','pipe']`,但代码**只读了 stderr**。mpv 的终端日志(状态行 + 每次 `loadfile` 一坨 `[component]` 行)几乎全写 **stdout** —— 没人读 → 那个 OS 管道缓冲区被填满 → mpv 下一次 `write()` **阻塞** → 整个播放器冻住。重启 = 全新空管道,所以"必须重启才好"。**切台每次吐一坨**,所以几次就犯;单看本地文件写得少,基本撞不到,故一直潜伏到 IPTV 才现形。
- **意外的对照实验**:临时把 mpv 开到 `--msg-level=all=v`(狂灌 stdout)→ 几乎秒卡;加上 stdout 排空 → 怎么都复现不出来。这一翻转锁死了病因。
- **修复**:stdout 也接上 `on('data', …)` 排空(直接丢弃,免得状态行刷屏 dev 终端;真报错仍走 stderr → `log` 事件)。**通用铁律:任何 spawn 出来的子进程,每一路 piped 流都必须读掉,否则缓冲区一满就把子进程憋死。**(项目里 MediaInfo 探测、yt-dlp 下载都已在读各自的 stdout,安全。)
- **诊断插曲**:一开始日志根本抓不到,正是因为老代码只监听 stderr(几乎是空的)——同一个 bug 的另一面,顺带修好;现在 dev 里 `[mpv]` 也能打了(默认只放行 stderr,不刷屏)。

- **打开即刷新**：`loadFavCollection` 重新抓源（URL 源拉最新频道、本地文件吃改动）并回写快照，**离线/失效则回落快照**；存的播放列表只播快照 items，不重抓。

### 硬核踩坑（发布前逮到的，别重走）
- **`force-media-title` 必须在 `loadFile` 之后设**，不能之前 —— mpv 自己 load 时的 `path` 事件会重置渲染层标题，之前设的会被抹掉、标题栏掉回丑陋的 URL 尾巴（`playlist.m3u8`）。
- **IPTV 频道绝不走 yt-dlp** —— `needsYtdl` 靠「URL 不以媒体扩展名结尾」判定，会误伤 `.php`/带 query 的流地址 → 既跳了强制标题又错误 yt-dlp'd。用 `sourceType !== 'iptv'` 拦住；且 `media-title` 处理器对 iptv **不许覆盖** `urlTitles`（m3u 里的台名才权威）。
- **播放列表/频道行的 React key 用原始 index，不用 `it.path`** —— m3u 可能重复同一 URL（多源），key 撞了会在搜索过滤后留下**组外鬼影行**。

### 错误处理
- 缺文件 / 死源过去是**静默黑屏**（mpv 清了 spinner 但没画面、无 toast，`onEnded` 只认真 EOF 故队列里死条目不自动跳）。现：`playCurrent` 对**本地文件** `existsSync` 守卫 → toast「文件不存在,请检查文件」+ 跳下一个可播的；死流/URL 走 mpv end-file `reason==='error'` → toast。

### 遗留 / 待办

### 中文排版（排查过程比结论长，避免重走）
- **症状**：小字号中文「字字大小不一、高低不齐」（`双`重 `击`轻 `开`偏上），英文同字号正常。
- **根因 = 字体 hinting**。雅黑 / 雅黑 UI / 华文细黑都是为 96 DPI ClearType 做的重度 hinting，强行把笔画掰上像素网格，**笔画密的被掰得比笔画疏的多**。几乎不 hinting 的字体就没这问题。
- **定稿：`--ui-font: 'Segoe UI', 'SimHei', 'Microsoft YaHei UI', sans-serif`**（`:root[lang^='zh']`）。**黑体**当年被嫌弃正因为不做 hinting，而在高 DPI + 灰度抗锯齿下这恰是优点；且 **Windows 自带，零打包 —— 开发者看到的 = 用户看到的**。Noto Sans SC / 思源效果更好（实测），但不随 Windows 分发，**不能拿它调设计**。
- **西文字体必须排最前**：黑体自带的西文字形是半角、很丑，把 SimHei 放第一会让中文界面里所有英文都变难看。（最初把中文字体排前的理由是「一行一套字体，基线才齐」—— 这个理由**后来被证伪**：DevTools 的 Rendered Fonts 显示出问题那行本来就只有一个字体。）
- `--disable-lcd-text`（[index.ts](../src/main/index.ts)）：灰度抗锯齿替代 ClearType 次像素抗锯齿。浅色小字压深色底是次像素抗锯齿最差的场景（染 RGB 子像素 → 彩边，且每笔染的程度不同 → 显得粗细不匀）。用户实测「舒服一点」。
- `--ui-tracking: 0.02em`，只对中文（西文保持 `normal`）。曾试 0.04em，配黑体偏松。
- 空状态字号改偶数 px（150% DPI 下奇数/半像素会落在半个设备像素上）。
- **已排除、别再试**：字体回退混用（Rendered Fonts 实证单字体）；`letter-spacing: 0.02em` 有无（无差别）；`--disable-font-subpixel-positioning`（无效，已撤）；透明度 0.4→0.58（对整齐度无效，但可读性更好故保留）；**CSS `-webkit-font-smoothing`（Windows 上是空操作，Blink 只在 macOS 认它，已实测）**。
- **待观察**：黑体**只有一个字重**（无 bold 文件），中文走 `font-weight: 600/700` 会是**伪粗体**，汉字容易糊。目前用粗体的地方（`.set-sec` / `.track-sec`）还都是英文，第二步译成中文后会现形 —— 届时倾向**中文标题不用粗体**（中文本就靠字距和留白分层，不靠字重）。

### 最大化 → 磨砂永久死亡（已修）
- **症状**：最大化后空状态变黑；**缩回来也不恢复**，一直黑到重启。
- **根因是「最大化」这个窗口状态本身**（不是尺寸）—— 无边框全屏同样铺满整屏，磨砂从来没死过，这条对比锁定了病因。进入 WS_MAXIMIZE 会摧毁 DWM 背板，**`setBackgroundMaterial('acrylic')` 重申请无效，切 `'none'` 再切回（中间隔一拍以躲开 DWM 的「无变化」合并）也无效** —— 两种都试过，只有重建窗口才回来。
- **修法：假最大化**（[index.ts](../src/main/index.ts) `fakeMaximize()` / `unfakeMaximize()`）—— `setBounds` 到 `screen.getDisplayMatching().workArea`，**永不进入系统最大化态**。用 `preMaxBounds` 记还原点，`isMaxed()` 取代所有 `win.isMaximized()`。和当初「原生全屏 → 无边框全屏」是同一个套路。
- **Aero Snap / Win+↑ / 双击标题栏**仍会摸到真最大化 → `win.on('maximize')` 立刻 `unmaximize()` 再套我们自己的。这条路径会**灰一瞬但能恢复**，用户判定可接受。
- **坑**：`persistState` 必须存 `preMaxBounds` 而非当前 bounds，否则最大化时退出 → 下次开一个「工作区那么大的普通窗口」，再也缩不回去。
- 顺带抽出 `reassertBackdrop()`，`setWinOpacity` 也改调它 —— **全项目只有一处知道怎么复活磨砂**。

## 历史状态（2026-07-21 · Phase 4 右键菜单亚克力化 —— 磨砂化收官）

**阶段：右键菜单改成独立 Win11 亚克力窗口(`?win=menu`),UI 全部磨砂化完成。另修掉两个真 bug:磨砂会掉、逐帧长按乱跳。**

- **磨砂"一弄就没"的根因(两个叠加,已修)** —— 困扰很久、以为是玄学的问题:
  1. **`setOpacity(<1)` 会把窗口变成分层窗口(WS_EX_LAYERED),而分层窗口不能有 DWM backdrop** → OSC/面板每次淡入淡出都把亚克力弄死,且我们从不重设 → 一直是平的,只有最小化+还原(重建窗口)才回来。修法:所有 opacity 走 `setWinOpacity()`,回到完全不透明时**重新申请一次 backdrop**,且只在"真的降到 1 以下过"时才申请(否则每次都申请会闪)。
  2. **点 OSC 后把焦点弹回主窗** → OSC 变非激活,Win11 把非激活窗口的亚克力渲染成纯色。已删掉那段弹焦点(任务栏问题现在由无边框全屏+置顶解决,不再依赖它)。
- **Phase 4:右键菜单 → 亚克力窗口**：菜单窗是**纯展示层** —— 主窗照旧构建菜单(onClick 闭包全留在原地),序列化成纯数据发过去,菜单窗只负责画 + 报尺寸,点击回传 id 由主窗执行。避免了把 toast/URL 浮层/宽高比状态全搬进菜单窗。
  - **子菜单改为手风琴就地展开**(一次只开一个),不做飞出式:窗口是单个矩形,飞出要么被裁、要么留一块空的磨砂方块;就地展开也更适合触屏。基建与飞出式共用,以后想换只需改渲染那一小块。
  - **定位**:开菜单时定一次角(必要时翻转),之后展开**只夹取不翻转** —— 否则每次尺寸变化重算翻转会让菜单乱跳。
  - **动画调优(踩了一串坑)**:① `easeOutCubic` 前 30% 走完 70% 距离,长尾被读成"两步" → 换 **easeOutQuad**;② 收起时**窗口必须领先内容**,否则窗口比内容高的那条区域显示未重绘像素 = **叠影**;③ 展开/收起**感知时长要相等**(感知 = 内容动画的时长);④ 时长曾写在渲染层和主进程两处,改一处就悄悄失配 → 改为**主进程唯一来源,开菜单时下发**;⑤ `.ctx-win` 的 scrim 改为**铺满整个窗口**(`min-height:100vh`),内层另建 `.ctx-win-inner` 供测量 —— 否则窗口比内容高时会露出没加暗色的纯亚克力条。

  - **鼠标指针**:菜单打开会隐藏 OSC → 主窗进入 `.ui-hidden`(`cursor:none`),旧的 DOM 菜单靠全屏 `.ctx-backdrop` 保住指针,窗口版没有 → 新增 `ui:menu` 广播 + `.app.ui-hidden.menu-open { cursor: default }`。

> **标题栏透明 / 真磨砂 = 死路(已定论,勿再提)**
> 原始诉求是让标题栏**透出后面的桌面和窗口**(像空状态那样)。挡路的是 **mpv 那块不透明表面**:mpv 经 `--wid` 嵌入、铺满整个客户区,`--video-margin-ratio-top` 只把**画面**推下去,顶上那 32px 仍是 **mpv 自己画的黑**。它在 Chromium 合成层之后、却在窗口亚克力之前 → **CSS 再透明也只能透出 mpv 的黑,透不到桌面**(空状态能透,是因为那会儿 mpv 没在铺)。
> 改做独立亚克力子窗也没用:磨的是同一片黑 → 出来还是暗灰,**和现在的纯色看不出区别**,还白搭上去不掉的 DWM 阴影 + resize 时跟不上主窗的重绘缝(整条顶栏上比侧面板明显得多)。
> **纯色 `rgb(62,62,63)` 是这条路上的正确答案,不是妥协。**
- **OSC 磨砂回归修复**(关键)([index.ts](../src/main/index.ts)):Phase 1 给 OSC 加的 `focusable:false` **会让 Win11 拒绝渲染它的 acrylic backdrop**(退成纯灰,无磨砂)—— 面板 `focusable:true` 所以正常,OSC 不正常。改回 `focusable:true`;副作用(全屏点按钮激活子窗、抢前台)用 `oscWin.on('focus') → win.focus()` **把焦点弹回主窗**化解(OSC 无文本输入,不需保留焦点)。真机 A/B(`MMP_OSC_FOCUSABLE` env 开关)实锤是它。
- **无边框全屏 → 修任务栏冒头**([index.ts](../src/main/index.ts) `toggleFullscreen`/`syncFsTopmost`):原生 `setFullScreen(true)` 下 **Electron 忽略 `setAlwaysOnTop`**,所以点 OSC 抢前台那一帧 shell 会把任务栏弹出来、压不住。改成**无边框全屏**(铺满整块显示器 `screen.getDisplayMatching().bounds` + `setAlwaysOnTop(true,'screen-saver')`),置顶盖在任务栏 z 序上 → 任务栏那帧落在窗口后面、看不见。置顶与"app 是否在前台"绑定(`syncFsTopmost`,接进 `updateFocus`)→ Alt-Tab 切走自动松开、不赖在别的程序上;`fsWasMaximized` 记原最大化态、退出还原。
- **HDR 字幕亮度(定性 = mpv 引擎限制,非本项目 bug)**:`sub-hdr-peak`(文字/ASS)+ 新增 `image-subs-hdr-peak`(位图/PGS)都接了([index.ts](../src/main/index.ts) `applyMpvSettings` + `settings:set`)。但**真机 + IPC 实测**:PGS 字幕对 `image-subs-hdr-peak` 从 10→10000、`blend-subtitles` yes/video、`target-trc=pq` **全程零反应**(`sub-visibility` 关→开确认重合成有效)。查证 mpv issue #13673/#13680/#16523 —— gpu-next 的 HDR 字幕亮度**只对文字字幕生效,位图(PGS)引擎没接**。MPC 能压是渲染器层缩放叠加层,mpv 不暴露此开关。设置保留(对 SRT/ASS 有效)。曾试 `--blend-subtitles=yes` 已回退(对 PGS 无用 + 会让 SVP 补帧把字幕卷入插值)。

- **可编辑数字框**：Adjust 各项（Delay/Position/Size/Brightness）数字改为**可输入框**，回车/失焦解析并 **clamp 到 min/max**；范围按 mpv 放开（Delay ±1000s、Position 0–150、Size 0–10000%、Brightness 0–100%）；框内打字/方向键不穿透触发播放器快捷键。
- **进度条位置**：`.osc-seek` 用 `position: relative; top: -8px` **只上移进度条**、按钮行不动、OSC 高度不变。
- **动态右面板宽 + 派生最小窗宽**：面板宽随窗口 `clamp(窗宽 − OSC_MIN(480) − 80, 300, 440)` —— ≥1000 满 440,越小越窄到 300,始终保证 OSC ≥480 不挤变形；主进程 `panelW()` 算、resize 时 `pushPanelWidth` 推给渲染层写 `--panel-w`,OSC 布局用同一函数。**窗口最小宽 = 300+480+80 = 860**(派生,`fitWindowToVideo` 下限同步)。面板边加 `width` easeOutExpo 过渡(拉窗口时边缘平滑跟随;OSC 独立按目标宽摆放,不受影响)。标题栏文字调暗到 `--text-dim`。
- **已知固有限制(诊断确认)**：无边框窗口 resize 时右/下侧有条**重绘延迟缝**(拖越快越大、松手即合)。实测切 `backgroundMaterial:'none'` 缝照旧 → **不是磨砂/DWM,是 Chromium 无边框窗口固有异步重绘**,无干净解(原生 window-proc 不值)。且 **主窗口 acrylic 是 mpv `--wid` 显示的必要条件**——切 none/不透明底会灰/黑屏,主窗口材质**不可改**。

### 黑屏根因（重要）
用 GDI 截屏做隔离诊断，逐步定位：
1. 透明窗口本身正常（绿底+红方块测试通过）。
2. mpv **单体独立窗口**能正常显示 + 被截屏捕获。
3. **把 mpv 用 `--wid` 嵌进 Electron(Chromium) 的窗口时，若该窗口页面不透明，Chromium 合成器会盖住 mpv 子窗口 → 黑屏。**
4. **解法**：单个**透明** Electron 窗口 + **透明页面** + mpv `--wid` 嵌入。mpv 子层在 Chromium 合成面之后，页面透明处透出视频，不透明控件浮于其上。**无需多窗口同步、无需原生模块。**

### 架构定案：单窗口
- 一个 `frame:false, transparent:true` 窗口，mpv `--wid` 嵌入。
- React：透明背景（透出视频）+ 标题栏/空状态/OSC（不透明元素叠加）。
- 放弃三窗口方案（复杂且不必要）。
- 已用 `MMP_TESTSRC=1` + GDI 截屏验证：真实 app 视频显示正常、OSC 两行布局叠加正常、标题栏正常。
